# 2. One 0.5s loop instead of per-tick, per-player functions

**Context:** the third-party Tameable Enderman pack ran its whole logic `as @a` every tick, so ~50 world-wide `@e` scans, 9 player-NBT reads, and 8 `data merge` calls per pet ran 20 × player-count times a second; on the server it coincided with ~140 ms ticks. **Decision:** Ender Pet has a single `schedule`d clock (`ender_pet:loop`, 10 ticks) with type-filtered selectors and `if items` checks (no NBT reads); player NBT (`SelectedItemSlot`) is read only on a click; timers count in 0.5s steps (trip 6, cooldown 8). **Why:** gameplay here (taming, following, fetching) doesn't need tick precision, and the clock's cost no longer scales with player count. Upgrade path if something does need precision: give that one feature its own faster `schedule`, don't move everything back to `tick`.
