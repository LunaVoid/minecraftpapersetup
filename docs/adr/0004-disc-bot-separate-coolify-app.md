# 0004 — Disc bot runs as a separate Coolify app sharing the server's data volume

**Context:** Getting MP3s onto the server is the hard part of making discs (no drag-and-drop into a Coolify container), and the disc pack needs an HTTP endpoint players can download it from. The bot could be a second service in the Minecraft compose stack, talk to the server over RCON, or be its own app. **Decision:** `discord-bot/` deploys as a standalone Coolify Application (Dockerfile build from this repo) with a bind mount of only the plugin folder, `/data/coolify/services/3hwwvj1at9jcp0sxhgbcbzxn/minecraft-data/plugins/URLCustomDiscs` → `/data/plugins/URLCustomDiscs`; it writes MP3s into the drop folder and serves the disc pack, with no RCON and no game port. Moved here from the old `minecraftMusic` repo, where this was its ADR 0001. **Why:** the Minecraft stack stays untouched (prebuilt `itzg/minecraft-server`), bot changes redeploy without restarting Minecraft, and the bot can only touch the plugin's folder (not worlds or other plugins). Cost: the host path is coupled to that Coolify service ID; if the Minecraft service is recreated the mount must be updated. Disc creation stays an in-game command (`/disc create`, op-only) because the plugin's commands need a player.
