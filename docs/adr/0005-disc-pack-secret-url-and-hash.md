# 0005 — Disc pack is served at a secret URL path, pushed with its SHA-1

**Context:** Players' clients download the disc pack with a plain HTTP GET; they can't send credentials. Options were a public URL, Traefik basic auth with the password embedded in the URL (`user:pass@host`, which the server hands to every player anyway, and the client may not support), or an unguessable path. Separately, upstream pushes the pack URL without a hash, so clients can't cache it, and `server.properties` `resource-pack-sha1` goes stale the moment a disc is added. **Decision:** the disc bot serves exactly one read-only file at `/<PACK_TOKEN>/discs.zip` (token from env, bot refuses to start without it; nothing else is routed). The plugin pushes the pack with its current SHA-1, both after each create/delete and to every player on join, so `server.properties` `resource-pack` stays empty. **Why:** same secrecy as basic auth without the compatibility risk; read-only means abuse is at worst bandwidth, bounded by `maxSeconds` per disc; the hash makes clients re-download only when the pack actually changed. Upgrade path if the URL leaks: rotate `PACK_TOKEN` and `downloadResourcePackURL`, and add a Traefik rate limit.
