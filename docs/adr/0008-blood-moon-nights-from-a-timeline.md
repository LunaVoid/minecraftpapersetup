# 8. Blood Moon nights come from a timeline, not a dice roll

**Context:** players wanted the sky to actually turn red. In 26.3 sky, fog and light colours are environment attributes driven by timelines, and the client evaluates the timeline itself from the world clock; there is no command to change them at runtime, so a night chosen by `random` on the server can't be coloured. (The moon is a texture and can only change with a resource pack.) **Decision:** `uncanny:blood_moon` is a 31-day timeline, added to `#minecraft:in_overworld`, that `alpha_blend`s red into sky/fog/cloud/sky-light colour on nights 3, 12 and 23; `blood/clock` reads the same timeline (`time query uncanny:blood_moon`) to start and end the gameplay. **Why:** one source of truth keeps the red sky and the buffed mobs in sync; the uneven 9/11/11-night gaps keep it hard to predict while averaging about 1 in 10. Cost: it's a schedule, not random; timelines are a registry, so changes to the JSON need a server restart rather than `/reload`; `/function uncanny:force/blood_moon` works by skipping time forward.
